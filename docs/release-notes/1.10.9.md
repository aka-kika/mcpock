mcpock 1.10.9, 2026-10-20. For macOS 26 or newer on Apple Silicon. Update from the app, or download it from mcpock.com.

Safer checks
- **Project .mcp.json files:** mcpock starts a project's server, and runs its header helper, only when you approved it in Claude Code for that folder.
- **Files only the scan found:** a server from a file no agent mcpock knows reads shows Paused until you choose Resume once (since 1.11: Waiting for your OK, until you choose Allow this file). Files mcpock already checked before this update keep working.
- **Your keys stay with your server:** a remote server can no longer point mcpock, or a redirect, at another host and get your headers.
- **aka:** mcpock asks aka's local helper for its servers only when aka itself is the program on that port.

Fixes in 1.10.9
- **Variables in configs:** `${VAR}`, `${env:VAR}` and `${workspaceFolder}` are filled in before a check, so working servers no longer read broken. One mcpock can't fill reads Not checked.
- **Project commands:** a command like `./.venv/bin/python` is found in the project folder.
- **Plain http:// servers:** servers on your own network or tailnet are reachable.
- **Needs <App> open, only when true:** only the program a launcher starts counts, and no port is guessed.
- **Clear errors:** a server that refuses mcpock's first message shows its own error at once instead of Slow.
- **Apps with their own flag:** an app started as its own MCP server is no longer started as a script.
- **Longer messages:** a remote server that splits an answer over several lines reads healthy.
- **Lighter on your Mac:** at most 6 checks run at once, and a server that leaves a process behind no longer leaves mcpock threads waiting.
- **Status file problems:** if mcpock can't save the file your agents read, Settings > General says so.
- **Agents ask first:** the instructions agents get now say to tell you what mcpock reports and ask before changing a config.
- **Helper:** mcpock-mcp knows mcpock is not running, also after a crash.
- **Cursor usage:** Cursor's database is read in place, never copied.
- **Update window:** the update window shows these notes.
